# Legion quest log map points

The world database held 18 definitions without coordinates across six of the eight affected quests. The two Tomb of Sargeras quests lacked both definitions and points. The migration adds eight definitions and 26 points. Definitions and coordinate sets already present at an index retain their contents.

The outdoor raid waypoint is approximate at 64.0, 21.4 on the Broken Shore map. It marks access to the raid for both quests. It supplies no guidance to the individual encounters inside the raid. The native Map record for 1676 does not supply an entrance through CorpseMapID. The positional evidence is the description of the [July 2017 entrance recording](https://www.youtube.com/watch?v=zcHik5KRX5Y). The video itself was not reviewed. Blizzard's [original raid preview](https://worldofwarcraft.blizzard.com/en-us/news/20783382/schlachtzugsvorschau-und-zeitplan-das-grabmal-des-sargeras) establishes the raid location and encounter context.

The 24330 coordinates come from the local TDB 735.00 archive. The other coordinates use build 0 to identify local placement, archival cross-version XY or the reconstructed entrance waypoint. The four existing guides 41195, 41778, 42602 and 45866 were excluded from the migration. The PvP weeklies 44891, 44908 and 44909 use matchmaking and have no static destination.

Two MariaDB shadow applications produced identical results. The fixtures seeded a custom coordinate set, an orphaned point and a changed phase requirement. Each protected index was preserved. Expected point count, quest count and unchanged comparison rows passed. The supplemental standalone AreaPOI catalog probe failed with access and heap errors and did not establish an original raid entrance pin. The successful typed WorldMapArea range read and the recorded entrance description provided the waypoint instead. Canonical diagnostic inventories did not change during the probes.

The canonical world updater registered migration `2026_11_24_15_warlock_quest_log_map_points.sql` as RELEASED and loaded 89,324 POI definitions. The readback showed 26 points across eight quests. Worldserver reached ready and the owned process shut down with exit 0. There were no fresh warning, error or assertion lines in the server log, appended DBErrors or new crashes. The canonical executable and protected runtime files retained their hashes. The local diagnostics and shadow readback are under `.codex/quest-log-map-points-20261124/`. Cleanup removed the isolated catalog executable and object file, reclaiming 607,272 bytes. Quest-map rendering in the 7.3.5 client remains unverified.
