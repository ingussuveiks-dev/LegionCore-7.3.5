# Mage Tower in the Legion calendar

The Broken Shore tower and War Councilor Victoria use world event 400. Its configured schedule has no client holiday ID. The calendar now reads the loaded event's start, end, period and duration when serving the native calendar. Every character receives an opening and a closing marker within the preceding 62 and following 400 days. Opening either marker shows both ends of that window in realm time. These entries live only in the calendar response and detail lookup. They create no character events or invitations.

The MariaDB record starts at epoch 1536649260. The 8,640-minute cycle and 4,319-minute duration give 28 November 2026 09:01 to 1 December 09:00 in Europe/Riga, followed by 4 December 09:01. Elapsed time matches the scheduler across daylight-saving changes. The last interval is clipped to the configured end. The Legion calendar list and detail field layouts were checked against the [packet decoder](https://github.com/TrinityCore/WowPacketParser/blob/50d58553/WowPacketParserModule.V7_0_3_22248/Parsers/CalendarHandler.cs).

The native calendar regression passed the November/December and October clock-change windows, exact closing and reopening boundaries, a truncated final interval, continuous availability, empty schedules and expiration. Release recompiled CalendarHandler.cpp and linked the ordinary game and scripts libraries. Both calendar handlers and the previous grain sack handler are present in the final map. The canonical executable matched staged SHA-256 `14FBE40E86AC5E3DBDA217CE2DE40AB51A7224B6DFDBEAA0771F7C2A2F57C8F4`. The calendar test added no canonical log bytes or crash files. No test worldserver or gameplay session was started. Calendar rendering and clicking the markers are pending the user's client check.

The empty-loot cursor and targeting before area damage still require client checks. The immediate prior executable and map are preserved under `.codex/fuzan-granary-20261126/rollback`.
